# 可接受使用、举报与申诉（v1）

[English](../policy.md)

## 可接受使用

在 RoamID 登记的应用不得用于：

- 钓鱼或冒充其他服务、组织或个人；
- 诈骗；
- 传播恶意软件；
- 在应用提供地违法的内容。

身份提供方在列入登记表前由人工审核（[registry.md](registry.md)）。应用由自动检查审核（[rp-integration.md](rp-integration.md) 第 12 节），通过即上线；检查发现不了的问题，经下述举报渠道交给运营方。

## 举报

任何人都可以举报应用或身份提供方：

- 在登录页点击「举报此应用」；
- 在应用的公开页面 `/apps/<client_id>`；
- 或在 `/report`。

表单包含类别（钓鱼或冒充、诈骗、恶意软件、违法内容、其他）、情况说明，以及可选的联系邮箱，并由 Orbit Verify 保护。

RoamID 保存举报内容、从登录页举报时进行中的登录的标识（应用与身份提供方 id，不含个人信息）、可选的邮箱地址，以及举报者网络地址的单向哈希。该哈希只用于统计不同举报者的数量。

举报本身不会改变任何状态。它进入运营方队列，24 小时内不同举报者的数量决定其优先级。

## 运营方处理

运营方在 `/admin/reports` 审核举报，并可以注明原因（所有者可见）执行：

| 处理 | 效果 |
|---|---|
| 驳回 | 关闭待处理的举报。 |
| 警告 | 原因在控制台向所有者显示。 |
| 暂停 | 在选择页之前拒绝登录（`app_suspended`）；应用收到 `access_denied`；`/token` 拒绝该应用。临时措施。 |
| 封禁 | 用于违法站点。与暂停相同，但不把用户送回应用，其域名不能再用于其他应用。 |
| 恢复 | 检查通过时回到 `active`（或 `development`）。 |
| 解除限额 | 提前结束新应用的每日登录限额。 |

每次处理都记录时间、运营方与原因。所有者在控制台的记录中可以看到自己应用的处理。

身份提供方仍由人治理：通过把 `status` 改为 `disabled` 的登记表拉取请求退役。紧急情况下运营方可以立即停用某个身份提供方（实例保存的覆盖开关），在运营方撤销前它在各处都视为已停用。

## 申诉

被暂停或封禁的应用的所有者可以在控制台的应用页面申诉。申诉在运营方队列中新建一项。运营方以恢复应用或维持处理作答，结果都会记入记录。
