# 可接受使用、举报与申诉（v1）

[English](../policy.md)

## 可接受使用

在 RoamID 登记的应用不得用于：

- 钓鱼或冒充其他服务、组织或个人；
- 诈骗；
- 传播恶意软件；
- 在应用提供地违法的内容。

身份提供方与应用都由自动检查审核（身份提供方：域名证明等，见 [registry.md](registry.md) 第 5 步；应用：[rp-integration.md](rp-integration.md) 第 12 节），通过即上线；检查发现不了的问题，经下述举报渠道交给运营方。

## 举报

任何人都可以举报应用或身份提供方：

- 在登录页点击「举报此应用」；
- 在应用的公开页面 `/apps/<client_id>`；
- 或在 `/report`。

表单包含类别（钓鱼或冒充、诈骗、恶意软件、违法内容、其他）、情况说明，以及可选的联系邮箱。表单按网络地址限流；实例可另加人机验证。

RoamID 保存举报内容、从登录页举报时进行中的登录的标识（应用与身份提供方 id，不含个人信息）、可选的邮箱地址，以及举报者网络地址的单向哈希。该哈希只用于统计不同举报者的数量。

表单注明：「若举报成立，其内容可能在不含联系方式的情况下公开。」举报者可以勾选「不公开我的情况说明」，此后公开该举报时只显示类别与处理结果。

举报本身不会改变任何状态。它进入运营方队列，24 小时内不同举报者的数量决定其优先级。

## 运营方处理

运营方在 `/admin/reports` 审核举报。每项处理都注明依据：运营方勾选该处理所依据的待处理举报，只有这些举报被认定成立，其余举报保持待处理。没有勾选举报的警告、暂停、封禁与身份提供方停用，只能作为运营方主动处理，不认定任何举报。运营方可以注明原因（所有者可见）执行：

| 处理 | 效果 |
|---|---|
| 驳回 | 将勾选的举报关闭为不成立。不公开。 |
| 警告 | 原因在控制台向所有者显示。 |
| 暂停 | 在选择页之前拒绝登录（`app_suspended`）；应用收到 `access_denied`；`/token` 拒绝该应用。临时措施。 |
| 封禁 | 用于违法站点。与暂停相同，但不把用户送回应用，其域名不能再用于其他应用。 |
| 恢复 | 检查通过时回到 `active`（或 `development`）。 |
| 解除限额 | 提前结束新应用的每日登录限额。 |

每次处理都记录时间、运营方与原因。所有者在控制台的记录中可以看到自己应用的处理。

身份提供方仍由人治理：通过把 `status` 改为 `disabled` 的登记表拉取请求退役。紧急情况下运营方可以立即停用某个身份提供方（实例保存的覆盖开关），在运营方撤销前它在各处都视为已停用。

## 公开记录

运营方的每一项处理都公开：应用的警告、暂停、封禁与恢复；身份提供方的紧急停用及其撤销。

| 公开 | 从不公开 |
|---|---|
| 应用或身份提供方 id、已证明的域名、举报类别、日期（UTC）、处理结果与一句话原因。 | 举报者的身份、邮箱或网络地址哈希；举报时进行中的登录；运营方的标识。 |

- 记录可在 `/transparency.json` 读取（只读，以 `?after=<n>` 分页），并每小时同步到本仓库的 `transparency/YYYY/MM.md` 与 `transparency/YYYY/MM.json`。
- 举报内容只在运营方于处理后对该举报选择「公开举报」时公开。运营方先编辑脱敏副本：删除邮箱与电话号码，链接改为不可点击的形式（`hxxps://example[.]com`）。公开的举报同时以标签为 `report-upheld`、标题为「Report: <类别> — <对象 id>」的 issue 发布。
- 公开的举报链接到认定其成立的那项处理。被驳回的举报默认不公开；运营方明确选择公开时标注「Not upheld」（不成立），不链接任何处理。驳回与解除限额不进入公开记录。
- 举报者选择「不公开我的情况说明」时，只公开类别与处理结果。
- 误发布的条目标记为已撤回并注明原因，不会删除。

## 申诉

被暂停或封禁的应用的所有者，或身份提供方的联系人，可以通过以下方式申诉：

- 在控制台的应用页面；
- 或使用本仓库的「Appeal a decision」issue 表单（`appeal.yml`），每条处理记录都链接到该表单。

申诉在运营方队列中新建一项。运营方以恢复应用或维持处理作答，结果都会记入记录与公开记录。
